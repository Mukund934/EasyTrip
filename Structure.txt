EasyTrip — repository structure
Regenerated 2026-08-10 from the tracked file list. Directory-level rather than
file-by-file: the previous version named individual files and 14 of the 37 it
listed no longer existed, because the Phase 5 cleanup deleted them and nothing
updated this file. A tree that has to be hand-edited on every refactor will
drift again, so this one describes shape and responsibility instead.

EasyTrip/
├── backend/                      Express 4 API, CommonJS, PostgreSQL
│   ├── app.js                    Entry point: middleware, routes, error handler.
│   │                             Listens only when it is the process entry point.
│   ├── script/                   Operational scripts (migrations runner, make-admin)
│   ├── src/
│   │   ├── config/               DB pool, Firebase Admin init, Cloudinary, env
│   │   │                         validation, schema.sql, migrations/, seed.js
│   │   ├── controllers/          Request handling, split by domain
│   │   │                         (place / image / review / taxonomy, auth, admin,
│   │   │                         newsletter) + controllers/helpers/
│   │   ├── models/               Parameterized SQL data access
│   │   ├── routes/               Route tables with express-validator rules
│   │   └── utils/                Auth middleware, error handler, logging, multer
│   └── tests/                    Jest + supertest against a real Postgres
│
├── frontend/                     Next.js 13 (Pages Router), React 18, Tailwind
│   ├── src/
│   │   ├── components/           UI, grouped by feature: admin/, browse/, home/,
│   │   │                         map/, place/, plus shared components
│   │   ├── config/               Firebase client initialisation
│   │   ├── constants/            Shared enumerations
│   │   ├── context/              AuthContext — the app's auth contract
│   │   ├── hooks/                Data and interaction hooks extracted from pages
│   │   ├── pages/                Routes, including admin/ and places/[id]
│   │   ├── services/             API client, one axios instance, one error shape
│   │   ├── styles/               Global CSS
│   │   └── utils/                Pure helpers: filters, dates, ratings, images
│   ├── public/                   Static assets
│   └── tests/                    Jest + React Testing Library (jsdom)
│
├── e2e/                          Playwright journeys against the real stack
│   ├── global-setup.js           Provisions Postgres + API before the suite
│   ├── global-teardown.js        Destroys them after
│   └── tests/                    Browser specs
│
├── scripts/                      Repo-wide checks (module-size architecture guard)
├── .github/workflows/            CI: lint/build, component tests, migrations,
│                                 API tests, E2E
├── docker-compose.yml            Local Postgres for development
├── playwright.config.js
└── README.md

Not in the public repository: `docs/` is a private engineering knowledge base
(roadmap, audits, decisions, session notes) and is deliberately gitignored.
